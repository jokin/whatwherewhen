# Handoff: Elsewhere '26 — What Where When (WWW)

> **Status: implemented.** The production Vite + React + TypeScript PWA lives in this repo
> (`src/`, `public/`, `vite.config.ts`). `npm install && npm run dev` to develop,
> `npm run build` to build. Deploys to Netlify via `netlify.toml`; pushes to `main`
> trigger automatic deploys. The original prototype files below are kept as the design reference.

## Overview

A mobile-first festival guide app for **Elsewhere '26**, a Burning Man–style festival in Monegros, Spain (7–12 July 2026). The app lets attendees browse 677 events across 37 camps, filter by day and category, save favourites, view camps on a map, and export their personal schedule to any calendar app.

## About the Design Files

The files in this bundle are **high-fidelity HTML/JSX prototypes** — they define the exact intended look, interactions and behaviour of the app. Your task is to **recreate this design in a production Vite + React codebase**, deploying as a PWA to Netlify. Do not ship the prototype files directly — they use browser-transpiled Babel and window globals, which are not suitable for production.

## Fidelity

**High-fidelity.** The prototypes are pixel-perfect with final colours, typography, spacing, interactions and animations. Recreate them faithfully using the design tokens and component descriptions below.

## Data Model

### Event object

```ts
interface Event {
  id:    string;       // unique, e.g. "ev-001"
  title: string;
  camp:  string;       // camp name, matches camps[]
  loc:   string;       // sublocation within camp, may be empty
  desc:  string;       // longer description
  time:  string;       // "HH:MM" 24h, or "00:00" for all-day
  dur:   number;       // duration in minutes, 0 if unknown
  cat:   string;       // category key (see CATS)
  days:  string[];     // array of day keys, e.g. ["Tue","Wed"] for recurring
  recur: boolean;      // true if it runs every day in days[]
}
```

### Camp object

```ts
interface Camp {
  name:  string;
  count: number;       // total events this edition
  x:     number;       // map position 0–100
  y:     number;       // map position 0–100
}
```

### Data file

`events-data.js` → rename to `events.json`. Strip the `window.WWW =` prefix and trailing `;`. The JSON has two top-level keys: `events` (array) and `camps` (array). Import with:

```ts
import data from './data/events.json';
const { events, camps } = data;
```

## App Shell & Routing

No router library needed. Single component `App` holds:

```ts
const [tab, setTab]     = useState<"Browse"|"Map"|"Mine">("Browse");
const [saved, setSaved] = useState<Set<string>>(() => {
  try { return new Set(JSON.parse(localStorage.getItem("elsewhere-saved-2026") || "[]")); }
  catch { return new Set(); }
});

const handleSave = (id: string) => {
  setSaved(prev => {
    const next = new Set(prev);
    next.has(id) ? next.delete(id) : next.add(id);
    localStorage.setItem("elsewhere-saved-2026", JSON.stringify([...next]));
    return next;
  });
};
```

The `saved` set and `handleSave` are passed down as props to all three views.

## Screens

### 1. Browse View

The main event listing. Full description:

**Layout (top → bottom):**
1. StatusBar (30px)
2. AdmitStrip (absolute, left side — see component)
3. Masthead — "ELSEWHERE '26 · MONEGROS" in fMono, then three stacked Ransom words: WHAT / WHERE / WHEN. "THE GUIDE" stamp top-right (rotated 7°, accent border)
4. SearchInput
5. DayTabs — one tab per day, tap to scroll-jump to that day's section
6. CatChips — horizontally scrollable category filter chips
7. NowStrip — up to 2 recurring events for the active day (accent/hi background strip)
8. Scrollable event list — infinite, day-grouped with headers
9. Nav bar

**Collapsed state:** once user scrolls >56px, the masthead + search + tabs + chips collapse into a slim 46px bar showing: Ransom logo | current day + filter summary | "Filters ⌄" toggle. Tapping "Filters" slides down an overlay panel with SearchInput + CatChips.

**Day tabs behaviour:** tapping a tab does NOT filter — it scroll-jumps the list to that day's section header. Scroll-spy updates the active tab as the user scrolls.

**Infinite scroll:** render in batches of 50 items. Load more when within 900px of bottom.

**State:**
```ts
query: string        // search text
cat: string          // active category key ("" = all)
activeDay: string    // current day (scroll-spy + tab)
limit: number        // items rendered so far
collapsed: boolean   // header collapsed?
filtersOpen: boolean // filter overlay visible?
sheet: Event | null  // event sheet open?
```

### 2. Map View

**Layout:**

**Orbit ring roads:** generated by `helpers.ts → orbitD()`. Two rings: outer (inflate 1.18, dashed brown stroke) and inner (inflate 1.0, semi-transparent fill + ink stroke). See helpers.js in the bundle for the full catmull-rom implementation.

## Components

### `<Ransom word size jitter />`

Renders a word as individual cut-out letter chips — each letter gets one of 5 alternating "cut" styles (different font, background, border), slightly rotated and offset to simulate a ransom-note collage. See `proto-ui.jsx` for the exact CUTS array and transform logic.

### `<StubCard event saved onSelect onSave index />`

Ticket-style event card:
- Left time column (52px wide, dotted right border): displays `HH:MM` or `✶` for all-day

- Main body: title (fUi bold, 2-line clamp), camp @ location, 1-line description clamp
- Left border: 5px solid in category colour

- Heart button: absolute bottom-right — filled ♥ (accent) when saved, outline ♡ (muted) when not

- Shadow: `1px 2px 0 rgba(38,48,42,0.14)`

Bottom sheet, slides up to 78% viewport height with dimmed backdrop.
- Entrance: `translateY(100%) → translateY(0)` over 280ms `cubic-bezier(.2,.8,.3,1)`
- Contents: drag handle + × close, category badge, title (fDisp 29px), time + duration + days row, camp/venue box, description text
- Footer: two full-width buttons — "♥ Save to Mine" (toggles, accent when saved) + "Done" (DS.hi)
- Escape key closes

---

### `<CalendarExportSheet events onClose />`

Bottom sheet, slides up to 86% height. Same entrance animation as EventSheet.

**Contents (top → bottom):**
1. Drag handle + × close
2. "ADD TO CALENDAR" label (fMono, DS.brown, letterSpacing 1.5) + "MY SCHEDULE" (fDisp 27px, DS.hi) + "{N} saved · {M} occurrences"
3. **Download .ics button** (DS.hi bg → DS.accent bg after download, full width, left ↓ icon box, title + subtitle). On click: generate ICS blob, trigger `<a download>`. Shows "✶ Downloaded! Open to import" for 3.5s after.
4. Platform hint box (DS.paper bg, fMono 9.5px): "iOS → Apple Calendar ✶ Android → Google Calendar ✶ Desktop → double-click to import"
5. Dotted divider: "OR ADD ONE BY ONE TO GOOGLE CALENDAR"
6. Per-day event rows, grouped by day with day headers. Each row: time | title + camp | `+ GCal ↗` link button (accent bg). Tapping a row opens `buildGCalUrl(event, day)` in a new tab.

**ICS generation rules:**
- One `VEVENT` per event × day (a recurring event on 3 days = 3 VEVENTs)
- `DTSTART` format: `YYYYMMDDTHHMMSS` (local, no timezone suffix — floating time)
- All-day: `DTSTART;VALUE=DATE:YYYYMMDD`
- Duration: if `event.dur > 0`, end = start + dur minutes; else end = start + 60 min
- `DTSTAMP`: `20260611T000000Z` (fixed — build date)
- ICS text escaping: `\` → `\\`, `,` → `\,`, `;` → `\;`, `\n` → `\n`

**Google Calendar URL:**
```
https://calendar.google.com/calendar/render
  ?action=TEMPLATE
  &text={encodeURIComponent(title)}
  &dates={startYYYYMMDDTHHMMSS}/{endYYYYMMDDTHHMMSS}
  &details={encodeURIComponent(description)}
  &location={encodeURIComponent(camp + " · " + loc)}
```

## Interactions & Animations

| Interaction | Behaviour |
|---|---|
| Browse header collapse | Collapses at scrollTop > 56, re-expands at < 10. Instant (no transition) to avoid jank |
| Bottom sheets | `translateY(100%) → 0`, 280ms, `cubic-bezier(.2,.8,.3,1)`. Backdrop fades in simultaneously |
| Escape key | Closes open sheets/overlays in order: event sheet first, then filter overlay |
| Cat chips drag | Pointer capture + `scrollLeft` manipulation. `touchAction: pan-x` |
| ICS download confirm | Button bg transitions accent for 3.5s, icon ↓ → ✶, text changes |
| Camp map selection | `scale(1.1)` + accent background, instant |

## State Management

No external state library needed. All state is local React (`useState`/`useMemo`/`useCallback`) with one cross-cutting concern:

```
App
├── tab: "Browse" | "Map" | "Mine"
└── saved: Set<string>  ← persisted to localStorage["elsewhere-saved-2026"]
    ├── BrowseView  (receives saved, onSave)
    ├── MapView     (receives saved, onSave)
    └── MineView    (receives saved, onSave)
```

Each view manages its own local UI state (search query, active day, sheet open, etc.).
